## 1. 使用说明

### 1.1 状态说明
- `TODO`：事项已识别，但尚未开始或尚未重新确认实施
- `IN_PROGRESS`：已确认开始实施，但尚未完成验收
- `DONE`：已明确验收通过
- `BLOCKED`：存在外部阻塞
- `DEFERRED`：明确后置

### 1.2 状态变更规则
- 讨论阶段：不修改状态栏
- 明确同意开始实施后，才能从 `TODO` 改为 `IN_PROGRESS`
- 明确验收通过后，才能从 `IN_PROGRESS` 改为 `DONE`
- 已实现但未验收的内容，只允许记录到“待验收记录”，不能直接写成 `DONE`

## 7. 决策记录

### 2026-03-25

- 确认长期上下文沉淀在仓库文档中
- 确认默认贴合当前项目架构和技术栈实现
- 确认协作方式调整为“先讨论计划、确认后实施、验收后同步状态”
- 确认注释风格默认贴合当前仓库现有写法
- 确认数据权限模型收口为：
  - `HQ`：`ALL / REGION / SELF`
  - `SERVICE`：`ALL / COMPANY / SELF`
  - `REGION` 只对 `HQ` 生效
  - `SELF` 只按 `assigned_user_id = 当前用户`
- 确认同一公司下多角色冲突时取最大范围：`SELF < REGION < COMPANY/ALL`
- 确认数据权限和操作权限分离
- 确认一级老板=`ALL`，一级派单员=`COMPANY`，一级工程师=`SELF`
- 确认二级老板=`COMPANY`，二级派单员=`COMPANY`，二级工程师=`SELF`
- 确认总部老板/主管=`ALL`，区域经理=`REGION`，总部派单员=`ALL`，总部工程师=`SELF`
- 确认数据范围选项不做后台业务配置，由后端规则元数据提供，前端动态渲染，后端保存时强校验
- 确认总部用户绑定大区时，必须按“当前选中的总部公司”局部替换，不影响该用户在其他总部下的绑定
- 确认用户切换到总部时，只加载当前总部公司的 `currentRegionIds`，不加载该用户在所有总部下的大区

### 2026-03-31

- 确认工单主状态基线为 `PENDING_ASSIGN / PENDING_TECH_ACCEPT / IN_PROGRESS / COMPLETED / CLOSED`
- 确认对外展示状态基线为 `WAIT_ACCEPT / IN_PROGRESS / COMPLETED / CLOSED`，其中 `WAIT_ACCEPT = PENDING_ASSIGN + PENDING_TECH_ACCEPT`
- 确认评价状态基线为 `NOT_OPEN / PENDING_EVALUATE / EVALUATED`
- 确认 `current_accept_subject_type / current_accept_company_id` 表示当前负责处理工单的主体和公司
- 确认 `assigned_user_id` 表示当前被派单维修员；转单时清空，完成/关闭后保留最后维修员快照
- 确认 B 端工单管理沿用 5 个内部状态，C 端及原型口径沿用 4 个外显状态
- 确认 `CLOSED + PENDING_EVALUATE` 的工单允许客户发起评价

### 2026-04-01

- 确认 `S0.4` 正式采用 `work_order / work_order_flow / work_order_participant / work_order_quote / work_order_repair / work_order_fault / work_order_review / work_order_evaluation / work_order_notify_event` 作为工单核心实体基线
- 确认工单主表只承载当前状态、查询快照和当前权限判断字段，动作事实与业务记录按独立表追加
- 确认历史参与方可见能力正式采用 `work_order_participant` 快照表，不再仅依赖流转历史联查
- 确认转单目标查询必须与转单动作权限保持一致，不能仅凭查看权限暴露目标列表
- 确认复检结果、故障描述等核心记录字段在应用层前置校验，并补充最小回归测试作为 `S0.4` 验收收口内容
- 确认 `S1.1-S1.3` 按 C 端后端 MVP 口径验收通过，包括建单最小合同、C 端鉴权、建单/查单闭环、服务网点选项与附近网点查询
- 确认 C 端建单只允许选择服务网点，不允许直接选择总部；现阶段服务网点暂不限制签约体系
- 确认条码归属总部正式数据源为 `machine_barcode`，C 端建单与条码预填信息优先使用条码档案，关系数据仅作过渡兜底
- 确认 `S2.1-S5.1` 按既有 5 个内部状态闭环验收通过，不新增“公司级接单”步骤，待接单仍指派单到维修员后的 `PENDING_TECH_ACCEPT`

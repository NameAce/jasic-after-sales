# 系统配置分组前端对接说明

> 本文用于前端对接 `sys_config` 分组改造后的接口。当前口径已经明确为：**按分组展示，按分组保存**。旧分页列表接口继续服务旧“参数设置”页；新分组配置页不要再拿分页接口拼装全部分组数据。

## 1. 接口选择

### 1.1 旧参数设置页

继续使用原接口：

```text
GET /system/config/list
POST /system/config
PUT /system/config
DELETE /system/config/{id}
```

用途：

- 旧“参数设置”页的分页维护。
- 单条新增、单条修改、单条删除。
- 兼容历史管理方式，不做下线，不做替换。

注意：

- `GET /system/config/list` 是分页接口，只返回当前页数据。
- 不适合用于新分组配置页一次性展示全部分组。
- 前端不要通过调大 `pageSize` 或循环翻页来组装系统配置分组页。

### 1.2 新分组配置页

#### 1.2.1 查询全部分组

```text
GET /system/config/grouped
```

用途：

- 一次性返回固定配置分组。
- 每个分组内返回当前分组下全部配置项。
- 前端可直接渲染为 tabs、分组块、折叠面板或分组表单。

请求参数：

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `includeLegacy` | boolean | 否 | `false` | 是否返回 `legacy` 历史废弃分组。新系统配置页通常不展示；排查历史配置时可传 `true`。 |

示例：

```text
GET /system/config/grouped
GET /system/config/grouped?includeLegacy=true
```

#### 1.2.2 按分组保存

```text
PUT /system/config/grouped
```

用途：

- 一次提交一个分组下的全部已编辑配置项。
- 后端在一个事务内逐条更新，避免前端自己拆成多次单条请求后出现部分成功、部分失败。
- 该接口服务新分组配置页，不替代旧参数设置页的单条增改删。

## 2. 返回结构

### 2.1 分组查询返回

接口返回 `Result<List<SysConfigGroupVO>>`。

```json
{
  "code": 200,
  "message": "操作成功",
  "data": [
    {
      "groupKey": "org",
      "groupName": "组织配置",
      "legacy": false,
      "configs": [
        {
          "id": 1,
          "configName": "公司管理员初始密码",
          "configKey": "org.company.adminInitPassword",
          "configValue": "Jasic@123",
          "configType": 1,
          "groupKey": "org",
          "remark": "创建公司时默认管理员账号的初始密码",
          "createTime": "2026-05-21 10:00:00"
        }
      ]
    }
  ]
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `groupKey` | 分组标识，固定为 `org`、`wechat`、`work_order`、`legacy`。 |
| `groupName` | 分组展示名称，可直接用于前端标题。 |
| `legacy` | 是否历史废弃分组。`true` 表示仅保留隔离，不作为新功能配置入口。 |
| `configs` | 当前分组下的配置项列表；分组无配置时返回空数组。 |

### 2.2 分组保存请求体

接口请求体为 `SysConfigGroupSaveDTO`：

```json
{
  "groupKey": "wechat",
  "configs": [
    {
      "id": 2,
      "configName": "B端小程序AppId",
      "configKey": "wechat.mp.b.appid",
      "configValue": "wx123456",
      "configType": 1,
      "groupKey": "wechat",
      "remark": "B端小程序接入AppId"
    },
    {
      "id": 3,
      "configName": "B端小程序Secret",
      "configKey": "wechat.mp.b.secret",
      "configValue": "abcdefg",
      "configType": 1,
      "groupKey": "wechat",
      "remark": "B端小程序接入Secret"
    }
  ]
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `groupKey` | 当前保存的目标分组。一次请求只能提交一个分组。 |
| `configs` | 当前分组下要保存的配置项列表。 |
| `configs[].id` | 必填。分组保存只用于更新已有配置项，不用于新增配置定义。 |
| `configs[].groupKey` | 建议直接回传查询接口返回值，也可以不传；如果传入，必须与外层 `groupKey` 一致。 |

成功返回：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": null
}
```

## 3. 分组口径

| groupKey | groupName | 前端展示建议 | 当前配置项 |
| --- | --- | --- | --- |
| `org` | 组织配置 | 展示 | `org.company.adminInitPassword` |
| `wechat` | 微信配置 | 展示 | `wechat.mp.b.appid`、`wechat.mp.b.secret`、`wechat.mp.c.appid`、`wechat.mp.c.secret`、`wechat.mp.b.bind.pagePath` |
| `work_order` | 工单配置 | 展示 | `default.hq.company.id` |
| `legacy` | 历史配置 | 默认不展示 | `wechat.notify.*` |

## 4. 前端实现建议

### 4.1 API 封装

已在 `jasic-ui/src/api/system.js` 增加：

```js
export function listGroupedConfig(params) {
  return request({ url: '/system/config/grouped', method: 'get', params })
}

export function updateGroupedConfig(data) {
  return request({ url: '/system/config/grouped', method: 'put', data })
}
```

### 4.2 页面加载

系统配置分组展示应调用：

```js
listGroupedConfig({ includeLegacy: false }).then(res => {
  this.groups = res.data || []
})
```

如需要排查历史废弃配置：

```js
listGroupedConfig({ includeLegacy: true }).then(res => {
  this.groups = res.data || []
})
```

### 4.3 保存建议

建议按下面的交互口径实现：

- 页面按分组展示。
- 用户在某个分组内编辑多个字段。
- 分组底部放一个“保存本组”按钮。
- 点击后仅提交当前分组的数据到 `PUT /system/config/grouped`。
- 保存成功后可只更新当前分组本地状态，或重新调用一次 `GET /system/config/grouped` 重新拉取。

示例：

```js
updateGroupedConfig({
  groupKey: activeGroup.groupKey,
  configs: activeGroup.configs
}).then(() => {
  this.$message.success('保存成功')
})
```

注意：

- `configValue` 允许空字符串，因为 `wechat.mp.b.bind.pagePath` 和 `default.hq.company.id` 默认值都留空。
- 一次请求只能保存一个分组，不要把 `org`、`wechat`、`work_order` 混在一个请求里。
- `configs[].id` 必须保留，后端按已有记录更新。
- 不允许前端自造分组值，只使用后端返回的 `groupKey`。
- `legacy` 默认不作为新配置入口；只有排查历史数据时才展示、保存。

## 5. 不要这样做

- 不要用 `/system/config/list` 循环分页拼出全部分组。
- 不要做“整页一次性保存全部分组”。
- 不要把 `legacy` 当作新配置入口。
- 不要新增前端自定义分组。
- 不要在前端硬编码完整配置项清单；配置项以接口返回为准。
- 不要重新接入 `wechat.notify.*` 历史配置链路。

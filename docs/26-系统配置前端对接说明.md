# 系统配置分组前端对接说明

> 本文用于前端对接 `sys_config` 分组改造后的接口。重点说明：旧分页列表接口继续服务“参数设置”页；新系统配置分组展示应使用非分页分组接口，不要用分页接口拼接全部分组数据。

## 1. 接口选择

### 1.1 旧参数设置页

继续使用原接口：

```text
GET /system/config/list
```

用途：

- 参数列表分页维护。
- 按参数名称、参数键名、是否内置、分组标识筛选。
- 保留旧“参数设置”页，不要求改成系统配置聚合页。

注意：

- 该接口是分页接口，只返回当前页数据。
- 不适合用于一次性展示所有配置分组。
- 前端不要通过调大 `pageSize` 或循环翻页来组装系统配置分组页。

### 1.2 系统配置分组展示

新增非分页接口：

```text
GET /system/config/grouped
```

用途：

- 一次性返回固定配置分组。
- 每个分组内返回当前分组下全部配置项。
- 前端可直接渲染为 tabs、分组卡片、折叠面板或分组表单。

请求参数：

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `includeLegacy` | boolean | 否 | `false` | 是否返回 `legacy` 历史废弃分组。新系统配置页通常不展示；排查历史配置时可传 `true`。 |

示例：

```text
GET /system/config/grouped
GET /system/config/grouped?includeLegacy=true
```

## 2. 返回结构

接口返回 `Result<List<SysConfigGroupVO>>`。

```json
{
  "code": 200,
  "message": "操作成功",
  "data": [
    {
      "groupKey": "org",
      "groupName": "组织配置",
      "legacy": false,
      "configs": [
        {
          "id": 1,
          "configName": "公司管理员初始密码",
          "configKey": "org.company.adminInitPassword",
          "configValue": "Jasic@123",
          "configType": 1,
          "groupKey": "org",
          "remark": "创建公司时默认管理员账号的初始密码",
          "createTime": "2026-05-21 10:00:00"
        }
      ]
    }
  ]
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `groupKey` | 分组标识，固定为 `org`、`wechat`、`work_order`、`legacy`。 |
| `groupName` | 分组展示名称，可直接用于前端标题。 |
| `legacy` | 是否历史废弃分组。`true` 表示仅保留隔离，不作为新功能配置入口。 |
| `configs` | 当前分组下的配置项列表；分组无配置时返回空数组。 |

## 3. 分组口径

| groupKey | groupName | 前端展示建议 | 当前配置项 |
| --- | --- | --- | --- |
| `org` | 组织配置 | 展示 | `org.company.adminInitPassword` |
| `wechat` | 微信配置 | 展示 | `wechat.mp.b.appid`、`wechat.mp.b.secret`、`wechat.mp.c.appid`、`wechat.mp.c.secret`、`wechat.mp.b.bind.pagePath` |
| `work_order` | 工单配置 | 展示 | `default.hq.company.id` |
| `legacy` | 历史配置 | 默认不展示 | `wechat.notify.*` |

## 4. 前端实现建议

### 4.1 API 封装

已在 `jasic-ui/src/api/system.js` 增加：

```js
export function listGroupedConfig(params) {
  return request({ url: '/system/config/grouped', method: 'get', params })
}
```

### 4.2 页面加载

系统配置聚合展示应调用：

```js
listGroupedConfig({ includeLegacy: false }).then(res => {
  this.groups = res.data || []
})
```

如需要排查历史废弃配置：

```js
listGroupedConfig({ includeLegacy: true }).then(res => {
  this.groups = res.data || []
})
```

### 4.3 保存配置

保存仍使用原接口：

```text
POST /system/config
PUT /system/config
```

请求体继续使用 `SysConfigDTO`：

```json
{
  "id": 1,
  "configName": "公司管理员初始密码",
  "configKey": "org.company.adminInitPassword",
  "configValue": "Jasic@123",
  "configType": 1,
  "groupKey": "org",
  "remark": "创建公司时默认管理员账号的初始密码"
}
```

注意：

- `configValue` 允许空字符串，因为 `wechat.mp.b.bind.pagePath` 和 `default.hq.company.id` 默认值都留空。
- `groupKey` 建议前端提交，后端也会按 `configKey` 兜底归组。
- 不允许前端自造分组值，只使用后端返回的 `groupKey`。
- 保存成功后如页面需要立即同步缓存，可继续调用刷新缓存接口；普通保存接口本身也会刷新当前 key 缓存。

## 5. 不要这样做

- 不要用 `/system/config/list` 循环分页拼出全部分组。
- 不要把 `legacy` 当作新配置入口。
- 不要新增前端自定义分组。
- 不要在前端硬编码完整配置项清单；配置项以接口返回为准。
- 不要重新接入 `wechat.notify.*` 历史配置链路。

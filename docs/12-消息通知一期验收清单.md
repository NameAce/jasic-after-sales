# 消息通知一期验收清单

## 1. 文档目的

本文档用于在实现过程中逐项确认一期消息通知功能是否真正落地完成。

使用方式：

- 每完成一个功能点就勾选
- 如未通过，记录原因和处理方式
- 阶段完成后同步更新分步落地方案文档

- [x] 已建立必要索引

## 3. 事件发布验收

- [x] 工单首次派单后会写入一条 `NEW` 状态事件
- [x] 工单实际派给维修员时才会写入 `WORK_ORDER_ASSIGNED` 事件
- [x] 工单公司转单不会错误写入 `WORK_ORDER_ASSIGNED` 事件
- [x] 事件记录包含 `eventKey`
- [x] 事件记录包含 `bizType/bizId/bizNo`
- [x] 事件记录包含 `oldAssignedUserId/newAssignedUserId`
- [x] 事件记录包含 `assignType`
- [x] 相同 `eventKey` 不会重复落库

## 4. 消息生成验收

- [x] 首次派单后，新接收人收到一条 `PENDING` 待办
- [x] 消息标题正确
- [x] 消息摘要正确
- [x] 消息保存了接收人快照
- [x] 消息保存了路由信息
- [x] 消息保存了工单绑定信息
- [x] 创建消息后写入了 `CREATE` 日志

## 5. 转派链路验收

- [x] 转派后旧接收人的 `PENDING` 待办变为 `INVALID`
- [x] 转派后旧接收人的 `READ` 待办变为 `INVALID`
- [x] 转派后旧接收人的 `DONE` 历史消息不会被改动
- [x] 转派后新接收人收到新的 `PENDING` 待办
- [x] 旧待办记录了 `TRANSFERRED` 失效原因
- [x] 转派链路具备幂等性

## 6. 已读链路验收

- [x] 进入工单详情页后，当前用户当前工单的 `PENDING` 待办变为 `READ`
- [x] 已读后记录了 `readTime`
- [x] 已读后写入了 `READ` 日志
- [x] 再次进入工单详情页不会报错
- [x] 已经 `READ` 的消息不会重复变更

## 7. 已处理链路验收

- [x] 接单动作触发 `DONE`
- [x] `PENDING` 消息可直接变为 `DONE`
- [x] `READ` 消息可变为 `DONE`
- [x] `DONE` 后记录了 `doneTime`
- [x] `DONE` 后写入了 `DONE` 日志
- [x] 重复执行相同完成动作具备幂等性
- [x] 前端没有直接改 `DONE` 的开放接口

## 8. 失效链路验收

- [x] 工单关闭时未完成待办变为 `INVALID`
- [x] 工单完成时未完成待办变为 `INVALID`
- [x] 当前系统无独立工单作废业务场景，本期不纳入验收范围
- [x] `INVALID` 后记录了 `invalidTime`
- [x] `INVALID` 后写入了 `INVALID` 日志
- [x] 已经 `DONE` 的消息不会被错误改成 `INVALID`

## 9. 查询与权限验收

- [x] 可查询待办红点数
- [x] 红点数等于 `PENDING + READ`
- [x] 可查询待处理列表
- [x] 可查询历史列表
- [x] 待处理列表只包含 `PENDING/READ`
- [x] 历史列表只包含 `DONE/INVALID`
- [x] 用户只能看到自己的消息
- [x] 用户不能操作别人的消息

## 10. 前端体验验收

- [x] 页面存在消息中心入口
- [x] 页面存在 `待处理 / 历史记录` 两个 tab
- [x] 点击消息先标已读再跳工单详情
- [x] 消息能正确跳转到工单详情
- [x] 顶部红点可正确显示
- [x] 工单处理动作成功后红点能刷新

## 11. 审计与排障验收

- [x] 已完成

# 消息通知多目标重构阶段三状态说明

> 本文档是 `docs/19-消息通知场景多目标重构方案.md` 在“阶段三：排障与收口”落地后的补充说明。
> 它不替代实施基线，只负责明确排障页、接口和人工处理使用的状态口径。

---

## 1. 排障视角

阶段三后的排障入口统一围绕“一个通知事件下有哪些通知目标产物”展开，不再以旧模板表、旧渠道表或最新一条通知记录作为主视角。

排障列表一行只代表一个 `notify_event`，并在同一行下拆开展示：

- 事件本身状态
- 同事件下的站内消息 / 站内待办产物汇总
- 同事件下的外部分发任务汇总

排障详情继续围绕单个事件展开，并能下钻到单条分发任务详情。

---

## 2. 状态口径

### 2.1 事件状态

事件状态只回答“这次通知事件是否被事件消费链路成功收口”：

- `NEW`：事件已入库，尚未开始消费
- `PROCESSING`：事件已被消费线程抢占，正在处理
- `SUCCESS`：事件消费成功，说明目标分流和产物落库已完成
- `FAILED`：事件消费失败，等待自动或人工重试
- `DEAD`：事件已进入死信，自动消费停止，等待人工介入

重点说明：

- `SUCCESS` 只表示事件消费链路完成，不等于所有外部分发都成功
- 事件详情仍需继续查看站内产物和外部分发任务

### 2.2 站内产物状态

站内消息和站内待办统一落在 `sys_notify_message`，但展示仍按目标类型区分：

- `IN_APP_MESSAGE`：站内消息
- `IN_APP_TODO`：站内待办

当前排障统一展示以下站内状态：

- `PENDING`：已生成，待处理 / 未读
- `READ`：已读
- `DONE`：已处理
- `INVALID`：已失效

重点说明：

- “站内消息已生成”不等于事件失败或成功，它只表示站内目标产物已经落库
- 即使事件失败，只要站内产物已存在，排障详情中也必须能看到

### 2.3 外部分发状态

外部分发统一落在 `sys_notify_dispatch`，当前主要对应 `MP_SUBSCRIBE`：

- `PENDING`：任务已创建，待 sender 发送
- `PROCESSING`：sender 已抢占，正在发送
- `SUCCESS`：发送成功
- `FAILED`：发送失败，仍可自动或人工重试
- `SKIPPED`：sender 或前置校验判定跳过，不再继续自动发送
- `DEAD`：进入死信，自动发送停止，等待人工介入

重点说明：

- `FAILED` 表示外部分发失败，不等于事件消费失败
- `SKIPPED` 用于明确区分 sender 主动跳过，例如接收地址缺失、配置不完整等
- `DEAD` 用于区分自动重试耗尽或人工终止后的最终停止态

## 3. 人工处理口径

### 3.1 事件重试

仅允许以下事件进入人工重试：

- `FAILED`
- `DEAD`

人工重试必须走 `NotifyEventService.resetForRetry`，统一清空：

- 状态
- 重试次数
- 下次重试时间
- 最近失败原因

### 3.2 分发重试

仅允许以下分发任务进入人工重试：

- `FAILED`
- `DEAD`

人工重试必须走 `NotifyDispatchService.resetForRetry`，统一清空：

- 状态
- 重试次数
- 下次重试时间
- 结果码
- 结果说明
- 渠道响应快照
- 发送成功时间

### 3.3 事件标记死信

仅允许以下事件人工标记死信：

- `NEW`
- `PROCESSING`
- `FAILED`

人工标记后统一进入 `DEAD`，并写入人工原因：

- `人工标记不再处理：{reason}`

### 3.4 分发标记死信

仅允许以下分发任务人工标记死信：

- `PENDING`
- `PROCESSING`
- `FAILED`

人工标记后统一进入 `DEAD`，并写入：

- `resultCode = DEAD_MANUAL_CLOSED`
- `resultMessage = 人工标记不再处理：{reason}`

---

## 4. 页面展示口径

排障列表与详情统一使用以下口径：

- 场景：展示 `sceneCode + sceneName`
- 目标：展示 `targetType + targetTypeDesc`
- 站内产物：展示每个目标下生成条数与状态分布
- 外部分发：展示每个目标下成功、失败、跳过、死信等状态分布

页面需要能直接看清以下差异：

- 事件处理失败，但尚未生成任何目标产物
- 事件处理成功，站内消息 / 待办已生成
- 事件处理成功，但外部分发失败
- sender 主动跳过
- 人工或自动进入死信

---

## 5. 剩余边界

本阶段仍保留以下边界，后续如需扩展应另起任务确认：

- 历史老数据若 `scene_code / target_type` 未完整回填，展示会尽量兜底，但不能保证完全具备新口径可读性
- 当前外部分发目标仍以 `MP_SUBSCRIBE` 为主，短信、邮件等新目标未纳入本阶段
- 排障页展示的是运行态产物和状态收口，不承担复杂报表统计职责

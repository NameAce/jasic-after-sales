# 佳士售后系统 - 小程序联调清单

> 本文档用于维护“小程序业务参考”与“当前系统后端 / PC 前端落地”之间的联调映射、已确认口径、待确认事项和后续推进顺序。
> 本文档默认参考 `mp` 目录下的小程序源码，不以小程序 mock 接口或小程序代码现状直接覆盖当前正式系统实现。

---

## 1. 使用说明

### 1.1 状态说明

- `已具备待复核`：当前正式系统已具备对应能力，当前重点是按小程序业务口径复核是否存在方向性偏差
- `待联调收口`：业务方向已定，但字段、入口、展示或边界仍需继续收口
- `已有正式结论`：该事项已有明确正式口径，本轮按该结论执行，不再反复讨论
- `本轮不纳入`：该事项已明确不纳入当前正式范围
- `待单独确认`：该事项仍会影响流程边界，需单独确认后再继续
- `后置观察`：暂不纳入当前批次，后续视业务需要再评估

### 1.2 使用边界

- 本文档中的“小程序”仅作为业务参考基线，不代表本轮实际改造对象。
- 本轮所有实际变更范围仅包括：
  - 后端
  - PC/Web 前端 `jasic-ui`
- 本轮不修改小程序代码。
- 如小程序现状与正式业务基线冲突，优先遵循：
  - 对话中已确认规则
  - `docs/00-实施清单.md`
  - `docs/00-小程序联调约定.md`
  - 本文档中的已确认联调口径

## 2. 当前总体判断

- 当前系统主业务方向与小程序表达的售后主流程没有明显偏差。
- 当前需要重点收口的，不是“页面是否长得像小程序”，而是业务主链是否一致、正式范围是否一致、PC 端现有页面是否能承接对应口径。
- 重新梳理后，当前联调主链建议按以下顺序理解：
  - 终端用户报修主链
  - 终端用户查单与评价主链
  - 承修方建维修订单主链
  - 承修方处理主链
  - 收尾主链
  - 转单与总部视图主链
